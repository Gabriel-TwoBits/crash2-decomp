# func_8001521C

Tears down a state object when `p[0] == 1`: calls `func_80012ED0(1)` if `D_8005F1A4` and `D_80067FB4` are set, `func_80051328(1)` if `D_80067FBC` is set, then `func_80034394`/`func_80032588`. It runs the 22 callbacks of a 0x1C-byte-stride table (`D_8005B1F0`) and `func_800155E0(p, i)` for each of `p[10]` entries. It frees `p[11]`, `p[0xA3C/4]` and `p[6]` through `func_800116C0`, clears `p[0]` and returns -0xFF (also when the state is not 1).

Final count: 0 of 74 words differ (`./score.sh match.c`).

What mattered:
- `D_8005F1A4` is `$gp`-relative in the target. A plain `extern s32` compiles to `lui`/`lw`; only an initialised definition in the file (`s32 D_8005F1A4 = 1;`) yields the `$gp` access. The definition is a probe artefact; in `src/` it must be the extern with the `$gp` access obtained another way.
- One counter variable for both loops (keeps `$s0` for it and `$s1` for the byte offset) and a separate `off += 0x1C`.
- An unused `char buf[8]` reproduces the 0x28 frame.
- `i = -0xFF; p[0] = 0; return i;` inside the block, with `return -0xFF;` outside, gives the original order of the `-0xFF` load and the store.
