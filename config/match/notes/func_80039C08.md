# func_80039C08

Interpreter-style opcode handler: decodes two 12-bit operands from `arg1` (the high one `arg1 >> 12`, then the low one).
An operand with bits 0xE00 set is either a push/pop on the stack pointer at `arg0+0xBC` (index 0xE1F, pre-decrement by 4)
or a register slot at `arg0 + 0x40 + (v & 0x1FF) * 4`; otherwise `func_80036D0C(arg0, idx)` resolves it.
It then pops two words (address and a packed value `>> 8`) and calls `func_80027600(w1, table[w0 >> 8], *dst, *src)`,
where `table = *(arg0->0xC + 0x24)`.

Tried: the m2c shape with inline pointer macros (66/73 differ), a static inline `Operand` helper (57), the same helper
with the index passed separately (56, `best.c`). Not matched: 56 of 73 words differ.

Still differs: the original keeps a copy of the masked index in `$a2` before the `0xE00` test and copies the pointer
result into `$s2` after the stack decrement; the compiled code decrements in place and branches differently
(`$s2` assigned directly). The control flow and the frame match.
