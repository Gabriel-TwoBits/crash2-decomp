# func_800171E8

## What it does

`arg0->0x10` points to a table with a word array at +0xC (count at +0x40); `arg0->0x1C` is an array of 12-byte records
(count at table +0x34). Unless `arg2` is the wildcard `0x6396347F`, it searches the word array for `arg2` (an entry with
bit 0 set is the id itself, otherwise a pointer whose +4 holds the id) and returns -0xFF if absent. Then, for each record
whose bits 10..12 of the halfword at +6 equal the found index (or all records for the wildcard): if `arg1`, calls
`func_80018474(record, table + 0xC)`; otherwise clears bit 9 of that halfword. Always returns -0xFF.

## What still differs (6 words)

Only the prologue's save order. Original: `sw $s1` first, then `$ra`, `$s5`..`$s2`, `$s0`; attempt7 saves `$s1` after
`$s2`. Without the `do`/`while (0)` (attempt3/4, 10 words) `$s1` comes first but `lui/ori` of 0x6396347F rise above the
saves. The original seems to need both: `idx = -1` in the saves' region (which forces `sw $s1` first) and `lui/ori`
after the loads. The `do`/`while (0)` is probably not the original's shape; another block boundary (a `while` loop for
the search, a nested block) is untested. Same class of difference as `func_80018CAC` in docs/COMPILER.md.

best.c = attempt7 (6 of 92).
