# func_80038700

Operand-driven vector op on an object. Bits 18-20 of `arg1` pick the mode: 0 (func_80028750 on reg 0 and a source reg,
half of the parent's +0x40 added to y), 1 (func_80028A28, plus func_80028C48 when the object is D_8005F38C or its +0x44
is), 2-5 (func_80028FE0 with a selector from the context flag at +0x29C and modes 3/5), 6 (func_800294B4).
Then the secondary result (callee-written, at buffer + 0x10) goes to the destination operand (skipped for 0xBE0; 0xE1F
pushes through obj+0xBC, other 0xE00 values index obj+0x40, the rest call func_80036D0C) and the primary result into
register `(arg1 >> 15) & 7`.

Callees write past their out vectors (the asm reads sp+0x50 / sp+0x60 afterwards), so those buffers are 8/16-word arrays.
func_80028750 is called with 3 arguments through a block-scope extern, since the file defines it with 2.
A static helper is `inline`d: the tester runs only this function's bytes, so a real call to it breaks.

Final: 500 of 500 trials agree on seeds 0 and 1 (about 340 of them end in the same exception, so coverage is partial).
