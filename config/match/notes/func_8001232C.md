# func_8001232C

Looks up a signed word in a relative-offset table of a header by type (`u16` at +2): types 0, 3-5 index through the word
at +8, type 0x100 through the word at +0xC, type 1 returns 0x10000, others return -0xE. A negative entry is returned
as `entry - header` (a relative offset made absolute).

Tried (4 attempts, 29 of 36 words differ at best; best.c = attempt2): `u16` vs `s32` type (signed compare needs `s32`),
a separate `base` copy of the pointer (the compiler folds it into `$a0`), `s32 *` indexing.
Still differs: the retail code copies `$a0` to `$a1` for the first path and the final subtraction, keeps the type in
`$v1`, and uses `$a0` on the 0x100 path. A source form that keeps two distinct pointer values live was not found.
