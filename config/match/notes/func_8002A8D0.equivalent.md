# func_8002A8D0 notes

Ray/segment test of a Y-range (`arg2` selects the upper or lower side, `arg3` clips to `arg1`'s Y range, `arg4`/`arg5`
bound the result, `-0x3B9AC9FF` meaning unbounded) against a collision volume, returning the hit height or
`0xC4653601` (no hit). `arg1` is an XZ box (`x0 y0 z0 x1 y1 z1`).

- Kind `obj[0] & 7`:
  - 0: axis-aligned box at `obj[2..7]`, grown by the pad read through `D_8005F38C` when bit 0 of the flag word is set;
    returns `obj[6]` (arg2 set) or `obj[3]`.
  - 1: oriented box. After the same range tests on `obj[11..16]`, the 8 corners are built, transformed in place by
    `func_8003EAD4`, and each of the 6 faces (`D_8005BBB8`, 4 corner indices each) with the wanted facing is tested:
    `func_80030680` for the XZ point inside the face, `func_80030498` for the height. The result is checked against the
    limits and, when `arg6` is not NULL, `arg6[0..2]` receives the offset of the lowest edge or corner from the face
    centre.
  - other kinds: no hit.

Result: `attempt1.c` (= `best.c`): 500 of 500 trials agree on seed 0, 499 of 500 on seeds 1 and 2 (3000 trials: 2999).

Remaining disagreement (one trial per seed): the trial ends in an access to an unmapped address in both versions, but at
addresses 8 bytes apart. The address comes from a corner pointer built from a `D_8005BBB8` index; the emulator's memory
holds a random word there, so the index is wild and the first of the face's corner loads to fault differs with the load
order GCC schedules. The real table holds 0..7, so the path is unreachable in the game. Reordering the loads in source
(temporaries, scalar pointers) did not change the order.
