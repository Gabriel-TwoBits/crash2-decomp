# func_800158E0 notes

Per-frame pad update over `D_8006991C` entries (stride 0x4C at `D_80069920`): shifts the button history, decodes analog
pads (id 0x53/0x73: calibrated stick, `ratan2` angle, direction, magnitude, byte-swapped inverted buttons), runs the
demo/playback state machine on `D_8006CD14` for pad 0, captures and clears pad 1, masks disabled pads, resolves the
direction bits, mirrors pad 0's angle/magnitude and stores newly pressed buttons in 0x24.

`best.c` = `attempt1.c`: the previous run's `earlier.c` with `D_8005F374` retyped to `s32 *` (the file declares it that
way; `earlier.c` did not compile as landed) and the byte-offset arithmetic cast through `u8 *`.

Result: 492 of 500 trials agree on seed 0 (earlier run: 493 / 492 on seed 1, 1980 of 2000). Not at 100%, so no `equivalent.c`.

Remaining disagreements: "retail makes 0 calls, candidate 2" (the analog path is reached only by the candidate). Every
branch of the assembly was re-read against the C (state machine, direction tables, divisions, clamps) and none differs.
Earlier experiments (`<<7` vs `*128`, volatile table, volatile stream flag, if-chain for the switch) did not change the
count. Most likely cause: trials with a large `D_8006991C` where the pad entries overlap the calibration table or code
area, so register-held vs reloaded values diverge; unconfirmed.
