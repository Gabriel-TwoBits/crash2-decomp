# func_800158E0 notes

Per-frame pad update. For each of `D_8006991C` pad entries (stride 0x4C at `D_80069920`):
- shifts the button history (0x24 -> 0x30, 0x28 -> 0x2C, 0x2C -> 0x34), clears 0x44;
- for a type-0 pad with id 0x53/0x73 (analog), scales the stick bytes (6, 7) against the calibration table
  `D_8006CDD0` (centre/min/max), clamps to [-0x80, 0x7F], derives angle (`ratan2`, optionally smoothed through
  `func_8001E640` when the camera flag 0x200000 is set), direction (0x40), magnitude (0x3C, dead zone 0x66) and the
  byte-swapped, inverted button word (0x28; id 0x53 also swaps bits 2/4/8/0x10/0x80); other ids get a neutral stick;
- pad 0: demo/playback state machine on `D_8006CD14` (3 clears buttons, 4 starts a stream via `func_8001CC10`,
  2 replays recorded button words from `D_8005F374`);
- pad 1: its buttons are copied to `D_8006CD6C` and cleared;
- masks buttons when the pad is disabled, resolves the 0x1000/0x2000/0x4000/0x8000 direction bits from the stick
  direction (or the reverse via the `D_8005B440` table), mirrors pad 0's angle/magnitude to `D_8006CD64`/`D_8006CD60`,
  and stores the newly pressed buttons in 0x24.

Files: `best.c` (= attempt1.c). The dead `bgez`/`addiu 0x1FF` after the `& 0xFFF` is omitted (value never negative).

Result: 493 of 500 trials agree on seed 0 (492 on seed 1, 1980 of 2000 at --trials 2000). Not at 100%.

Seed 2 (also 496 of 500 with an if-chain in place of the `unk_40` switch, so the jump table is not the cause) shows
the candidate making a call to 0x80400000 where the retail code calls `ratan2`: likely an emulator artifact of trials
whose large `D_8006991C` walks the pad entries over the scratch code area, not a path difference.

Disagreements on seed 0 and 1: "the retail code makes 0 calls, the candidate 2". Ruled out by experiment (no change in count):
`<<7` vs `*128`, volatile calibration table, volatile `stream_flag` (deferred `D_8005F3D8` load), extra per-iteration
work (instruction-limit effect). Still unexplained; most likely a fault or exit in the retail code before its first call
that the C does not reproduce (the camera pointer chain or the divisions are the remaining suspects).
