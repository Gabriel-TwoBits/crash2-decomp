# func_8001F054 notes

Walks a path (`func_80031AE8` points, `func_800322C0` count) to the segment given by the fixed-point position `pos`
(segment << 8 | fraction) and writes the segment's start point to `out`. With `obj+0xAC & 0x8000` it projects the object
(`+0x60`, `+0x68`) onto the segment, sets the distance `+0xA0` (signed by a cross product), the `+0xA8` flags (0x200 off
segment, 0x4 at the end, 0x10 edge changed) and `+0xD4` (clamped position); a fraction >= 0x100 retries on the next
segment. `+0xAC & 4` / `& 0x800` set the yaw/pitch fields (`+0x94`, `+0x74`, `+0x98`) with `ratan2`. Finally `out` moves
toward the next point by the fraction. Returns -14 without a path, 1 for a one-point path, else the point count.

Final: best.c (= earlier.c) agrees on 462/500 (seed 0) and 469/500 (seed 1), up from 305/291 before equiv.py learned to
leave trials that depend on unset registers uncompared. attempt1.c (loading the point's halfword before the base word)
changed nothing.

Still disagrees: the assembly reads `$s5`/`$s7` (base pointer, shift) without setting them unless the node's type is 7;
they carry the caller's values. The retail run uses the emulator's random `$s5`/`$s7`, the C reads uninitialised locals,
so the candidate faults or returns where the retail faults differently (e.g. seed 1 trial 27: retail address error after
3 calls, candidate 4 calls and returns). Not reproducible in plain C; every path of the assembly has its counterpart in
the C. Not copied to equivalent.c since not every trial agrees.
