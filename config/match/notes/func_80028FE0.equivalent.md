# func_80028FE0 notes

Probes an object's position (`arg1`, Y raised by 0x61A8) against the level list (`D_800608CC->0x10`: count at 0x190,
entries at 0x194, flags at 0x1B4), then against the table of boxes at `D_8006CB6C + 0x290`, and passes the resulting id
to `func_800289C4` (also for the linked object at +0x44 when `arg2 & 4`).

- Level list: each entry with flag 4 goes through `func_80014260` then `func_80030D74`; the first hit calls
  `func_8003DA00` (a3 and six scaled words on the stack in the assembly, through a function-pointer cast). Repeats while
  the result is null and the list was not exhausted; an exhausted list gives no hit.
- Boxes: Y mode (`arg2 & 1`) or Z mode (`arg2 & 2`); a box containing the start position ends the scan with a hit, else
  the highest top below the start is kept and applied after the scan when there was no hit or it is not above the current
  position. No mode: every box is skipped.
- Id: `hit->0x138` (negative: negated, `arg3` zeroed) for a box hit; bits 4..9 of the pointer (-1 outside 0x30..0x3F) for a
  level hit; -1 with no hit.
- The retail code returns the hit pointer in `$v0`; `game.h` declares `void`, so the C keeps `void`.

Result: `equivalent.c` (= `attempt3.c`): 2000 of 2000 trials agree on seeds 1 and 2 (`--trials 2000`), 500 of 500 on
seeds 0 and 1.

The earlier run's C (`earlier.c`, same logic) disagreed on 20 of 2000 trials. `attempt3.c` differs only in shape: the
level-list scan is a `do`/`while` that calls `func_8003DA00` inside the loop and assigns `found` from every
`func_80014260` call, and the box count is read once. The cause of the earlier disagreements was not isolated.
