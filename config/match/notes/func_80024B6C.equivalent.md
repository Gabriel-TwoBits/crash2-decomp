# func_80024B6C

Walks a path of 6-byte point records (3 x s16, fetched with `func_80031AE8`, count from `func_800322C0`) starting at the
position `path->pos` (24.8 fixed point) to find where a query point (`arg1`, three 24.8 words) reaches the distance
`arg2`. The distance of a point is either `(y - qy) << 8` (no plane flag in `arg5`) or a projection onto an axis pair
(`arg5 & 5`; `arg5 == 1` swaps the sign pattern, using `arg3` and `arg4` as the two coefficients). The walk goes
forward when `path->mode == 2`, backward otherwise, interpolating the crossing into `*arg6` and returning 0. When it
runs off the end it stores the best position and returns the remaining distance; after 3 steps without improvement it
stores the best position and returns -1.

best.c (= attempt2.c): 499 of 500 trials on seed 0 and on seed 1. The single disagreement in each is a trial where both
versions fault on garbage memory but at neighbouring addresses: the retail code loads only the fields the flag needs
(`y`, or `x` and `z`), the C loads all three of the first two points. A first attempt with a non-inlined helper made
the harness record the helper as a call (38 disagreements); `static inline` fixed it.

Not done: lazy field loads (only `y`, or only `x`/`z`) to match the faulting order; the equivalent.c criterion (every
trial agrees on two seeds) is therefore not met, so no equivalent.c.
