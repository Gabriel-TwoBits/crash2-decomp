# func_80019D30

Takes an object `p` and a value `a1`. If `p->0xB8 == 0`, `p->0 != 0`, `p->0x18 == a1`, bit 0x1000000 of `p->0xAC` and bit 0x40000 of `p->0x100` are clear, it calls `func_8001CC10(0, p, 0x1A00, 0, 0)`, then calls `func_80019BBC(p, 0)` if `p->0x18 == a1` or `D_800608D0 == -1`. Otherwise it returns -0xFF. After the `func_80019BBC` call it returns whatever is left in `$v0`.

Best: `best.c` (a2.c), 6 of 54 words differ. The control flow and calls line up. The `-0xFF` result is built in the branch delay slots, as in the target.

Still differs: the target copies `a1` into `$s1` at entry and compares it with a reloaded `p->0x18` (`bne $v0,$s1`). The compiler instead loads `p->0x18` into `$s1`, compares it with `$a1`, and reuses `$s1` after the call. Because the two values are equal on that path, it substitutes one for the other.
