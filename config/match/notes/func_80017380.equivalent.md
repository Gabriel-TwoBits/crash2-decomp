# func_80017380 notes

Computes a texture rectangle (`out[0..3]`) for one entry of a record. Entry pointer `p` is `base + (arg2 >> 8) * 16 + 8`
for type byte 2 or `* 24 + 12` for type 5; for any other type retail leaves `$s0` untouched (the caller's value) and
uses it as the entry. Calls `func_80018474(p + 4, base + 4)`, then by mode: 2 gives a VRAM position and width 0x10/0x100;
1 takes the min/max of three (x, y) byte pairs and scales x by the bit depth in bits 7-8 of the halfword at `p + 0xA`
(divide by 2, 4 or none).

Tried: the earlier `switch` version (55 of 500 trials agree), the same logic as `if` chains with named constants
(`attempt2.c` = `best.c`, 55 of 500), `p` declared last (same).

Still disagrees: types other than 2 and 5, which is nearly every random trial. Retail reads the caller's `$s0`; the
candidate's unassigned `p` lands in another register, so `func_80018474`'s first argument differs (7 vs 8 in trial 0).
Plain C has no way to pin it to `$s0` without inline assembly. For types 2 and 5 the logic is believed equivalent.
