# func_80038D08

Matched: `match.c`, 0 of 67 words differ (`./score.sh`, GCC 2.7.2).

## What it does

Decodes an instruction word `op` for an object with registers at 0x40 and a stack pointer at 0xBC:

- bits 0-11: destination operand. 0xE1F pops the stack, `0xE00 | n` is register `n & 0x1FF`, anything else goes through
  `func_80036D0C(obj, idx)`.
- bits 12-17: source operand. 0 means the value 0, 0x1F pops the stack, otherwise register `n`; the value is read.
- bits 20-23: a field passed on as flags, 0xF becoming 0x80000000; bits 18 and 19 add 0x40000000 and 0x20000000.

It calls `func_80032F18(value, flags, dst, obj)` and stores the result at 0xD4.

## What was tried

- m2c's draft: 62 differ (pointer arithmetic subtracted 16 bytes instead of 4 from the stack pointer).
- Plain C with a struct and `--obj->sp`: 62 differ, all from one missing `addu $a1, $a0, $zero` before the first branch,
  which shifted every later word. Changing the index's type (u32) or testing `idx & 0xE00` instead of `op & 0xE00` did not
  bring it back.
- Destination decode moved into a `static inline` helper taking the index as a parameter: the parameter copy produces the
  `addu`, 0 differ. The source decode stays in the function body.

The full probe across compiler versions (`tools/probe_compiler.py` without `--diff`) and the build's SHA-1 were not run here.
