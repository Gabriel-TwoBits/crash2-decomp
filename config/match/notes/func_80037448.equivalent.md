# func_80037448

Two-operand step of an interpreter-like VM. `arg1` packs two 12-bit operands (high one at bit 12, low one at bit 0).
An operand with `(x & 0xE00) == 0xE00` is a register word at `obj + 0x40 + (x & 0x1FF) * 4`, or, for `0xE1F`, a pop of the
stack pointer at `obj + 0xBC` (moved down 4 bytes first). Any other operand goes through `func_80036D0C`.
Both are resolved (first operand's word is read first), then a result word is pushed at the stack pointer (advanced 4 bytes):
`func_800321D4(obj->0xF0, second >> 8, first, 0, 0, 0, 0)` when `obj->0xF0` is non-zero, else 0.

Tried: m2c draft (wrong, scales byte offsets by 4 as pointer arithmetic), a static helper (adds a call), then a macro for the
operand decode. Memory read order matters for the exception trials (`*second`, then stack pointer, then handle).
Final: 500 of 500 agree on seeds 0 and 1. Operand decode is a macro to keep it inline.
