# func_800316EC notes

Reads the ISO9660 volume descriptor (sector 0x10), checks "CD001", prints, loads the root directory sector, and builds
a 4-entry LBA table from path-table-style records named `S<digit>` (index = second char - '0', unchecked store).
For each table entry it reads that sector and walks directory records (max 0x40; the first two are "." and ".."),
and for names starting with `S`/`s` computes an index from name[6], name[7] and stores LBA/size bitfields into
D_80069034/38/3C (12-byte entries), depending on name[0xB] being `D`/`d`.

Result: best.c, 491/500 (seed 0), 490/500 (seed 1). Not promoted to equivalent.c.

Remaining disagreements: the `table[name[1] - '0']` store is unbounded. In retail it lands on the callee-saved
register save area (sp+0x50..0x6C) for indices 8..15, corrupting registers/return. The C stack layout cannot reproduce
that, so those trials differ (TLB miss in retail, normal return in the candidate). The retail also leaves 1/0 in $v0
while the prototype is `void`, which is kept as declared.
