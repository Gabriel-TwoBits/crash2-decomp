# func_800316EC notes

Reads the ISO9660 volume descriptor (sector 0x10, "CD001"), then the sector at the root record's extent. Walks up to 0x80
path-table-like records, collecting extents of two-character `S<c>` names into a 4-entry table (index `name[1] - '0'`,
unchecked, as in the assembly), reads each listed sector, and walks up to 0x40 directory records (names `.`, `..`, then the
record's own). Names starting with `S`/`s` give a hex index from bytes 6-7; byte 11 `D`/`d` updates the 12-byte-stride
entries at D_80069034/D_80069038, otherwise D_8006903C. The buffer is freed with func_800116C0 on every path.

Tried:
- `earlier.c` (separate locals): 1999/2000 on seed 1; the unchecked table store lands elsewhere in the stack.
- attempt2: the locals as one struct (`Func800316ECLocals`: name, table, extent, path extent, size), copying the
  original frame's offsets (0x10, 0x30, 0x40-0x48). Fixed that trial; one other per seed still disagreed.
- attempt3: no `end` local (`sector + SECTOR_SIZE` in the loop conditions), so the register count, and with it the
  frame size (0x70) and saved-register slots, matches the original.

Final (`equivalent.c` = attempt3): 500/500 on seeds 0 and 1, 2000/2000 on seeds 1 and 2.

Out-of-range `S<c>` names write into the stack frame, so the C depends on GCC keeping the original frame layout; a
change that alters register use or locals can bring the disagreements back.
