# func_800189CC

Matched: `match.c`, 0 of 55 words differ (`./score.sh match.c`).

## What it does

Reparents a node in a tree: unlinks `node` from `node->parent`'s child list (singly linked through `+0x48`), then pushes it
at the head of `parent`'s list and sets `node->parent` (`+0x44`). A node's child-list head is `+0x4` when its word at `+0x0`
is 2, `+0x4C` otherwise. Returns -0x18 when `node` is not found in its old parent's list.

## What decided the match

- The search loop is `while (it != 0 ? it->next != node : 1) { if (it == 0) return -0x18; it = it->next; }`. The ternary
  in the condition holds a label, so GCC rolls the exit test to the loop's end (`expand_end_loop`) without copying it before
  the loop; the `: 1` arm sends a null `it` into the body, whose null test is the one the retail code keeps before the step.
  `&&` conditions, `for`/`while (1)` loops with `break`/`return`, and a goto copy of the retail layout all let GCC fold
  the redundant null test or reuse the loaded `it->next` (28 to 36 words off).
- The success path has no `return`: the retail code ends with `$v0` still holding the 2 loaded for the last
  `parent->unk0 == 2` comparison. `return 2;` (or an `rc` variable) adds an `ori $v0, $zero, 0x2` before `jr $ra`
  (5 words off). Callers should be checked before relying on that 2 as a real return value.
