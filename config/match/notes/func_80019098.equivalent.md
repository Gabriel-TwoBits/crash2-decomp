# func_80019098 notes

Spawns a game object into a slot: resolves the object handle (`arg0->unk10[arg1 + a + b]` when `arg0->type == 7`),
rejects it when its index flags (`D_8006B1C4`) are set, picks a slot (the player slot `*D_8006CB10` for kind 0 / index
1..4, otherwise a free one, scanning `D_8006CB18` with `func_80018BE4` until one is found), initialises it
(`func_80019988`, position, parent, clear 0x20 bytes), and links "chain" objects (kind 0x22) through `D_8006CDF0/F4/F8`.

Final: `best.c`, 553 of 3000 trials agree (82 of 500 on seed 0, 101 of 500 on seed 1). Not every trial agrees.

Known disagreement: when `arg0->type != 7` the retail code uses the caller's `$s2` as the object handle (an uninitialised
read; the only caller passes pointers from `func_80014260`). The C leaves `obj` uninitialised, but GCC does not keep it
in `$s2`, so those trials differ in the first `func_800321D4` argument. The first reported disagreement is always this one,
so other mismatches past it were not inspected. All branches of the assembly have counterparts in the C.
