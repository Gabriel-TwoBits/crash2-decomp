# func_800176DC

Copies an image rectangle between VRAM and up to two RAM buffers (`i3`, `i4`): LoadImage when `mode == 1`, StoreImage
otherwise. `func_80017380(2|1, a1, a2, &rect)` fills the RECT. A buffer not 16-byte aligned goes through an aligned bounce
buffer on the stack (`w * h * 2` bytes copied by hand); `flag` skips the DrawSync of the aligned path, is cleared on the
bounce paths and is returned (`include/game.h` declares it `void`; the retail code returns it in `$v0`).

Final: `best.c` (= `earlier.c`), 10 of 172 words differ, 2 instructions without counterpart. Only the prologue differs:
retail loads `i4` (`lw $s3, 0x158`) right after `flag`, before the argument moves; the compiled code loads it last.

Tried:
- `u8 *` parameters, K&R definition with reordered declarations: no change.
- Static inline helper called twice: 175 words. Swapping `buf`/`r` declarations: frame layout changes, 174.
- Modifying `i4` directly (`*i4++` in the Store copy loop) moves its load to the top as retail does, but then `flag` is
  loaded last and the registers shift (65 words); the same in the Load loop (95) or in all four loops (157) is worse.
  The `i4` load position does depend on whether its pseudo is ever assigned: a lead for the permuter or a later run.
- decomp-permuter, 5 min, from `earlier.c`: best candidate 27 words, none below the base's 10.
