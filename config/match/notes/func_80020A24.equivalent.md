# func_80020A24 notes

Scene setup: points the table pointers (`D_80062A18`..`D_80062A24`) at their fixed addresses, stores the camera-relative
position of `D_8005F38C`, reads the scene flags through `func_80031AE8` (entry 0x185) and, per flag bit, loads more
entries (0x186, 0x297, 0x2AA, 0x1B5-0x1B8, 0x1DE) into the `D_80062Axx` variables and installs the per-mode
function-pointer set in `D_80062A28`..`D_80062A38`. Last, when `D_8006CB94` has bit 0x01000000, builds a model reference
from "DirnD" and fills `D_80062AAC`/`AB0`/`AC8`.

Result: `equivalent.c` (= `attempt2.c`) agrees on 500/500 (seeds 0 and 1) and 3000/3000 (seed 2).

What mattered:
- m2c's draft, with `M2C_FIELD` turned into plain casts, scored 476/500 once it compiled.
- The retail frame is 0x50 bytes with the locals at 0x28..0x47; separate `s32` locals gave a smaller frame, so the
  `&sp28`/`&sp30` buffers sat at other addresses. One `s32 frame[8]` restores it (`frame[0]`, `frame[2]`, `frame[6]`).
- `func_80011E24` ignores its argument, but retail leaves the scene pointer in `$a0` at the call; the C calls it through
  an `s32` argument cast to match.
- `func_8002FC78` takes `void *` (the file's own definition), not `s32 *`.

Not covered by the trials: about two thirds end in the same exception (null or random pointers), so the code after those
points was checked against `target.s` by reading only.
