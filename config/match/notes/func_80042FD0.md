# func_80042FD0 — not matchable from C

Handwritten assembly (splat marks it `/* Handwritten function */`), not compiler output.

## What it does

A GTE helper with a register-only calling convention: it takes a 3x3 matrix of packed 16-bit
values in `$t0`-`$t4` (the layout of `MATRIX.m` as five words), multiplies it by the current
rotation matrix column by column (`mtc2` to VXY0/VZ0, three `mvmva` rotate-only passes with
`sf=1`, `mfc2` from IR1-IR3), and repacks the products into `$t0`-`$t4`. It has no `jr $ra`:
it falls through into func_80043074, which loads `$t0`-`$t4` into the GTE rotation matrix with
`ctc2` and returns. In effect the two are one routine, RotMatrix = RotMatrix x M, split by splat.

Callers (func_800437F4, func_800445B8, also handwritten) set `$t0`-`$t4` and `jal` it.

## Why no C can match it

- Inputs and outputs live in `$t0`-`$t4` and scratch in `$t8`/`$t9`/`$a0`; GCC's ABI never
  passes arguments or returns values there.
- No epilogue and no `jr $ra`: control falls into the next symbol, which a C function cannot do.
- GTE instructions (`mtc2`, `mfc2`, `mvmva`) need inline assembly, which the rules forbid.
- The interleaving of GTE loads with integer ops is hand scheduled around `mvmva` latency.
